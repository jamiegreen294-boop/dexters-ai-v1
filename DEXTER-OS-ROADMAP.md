# Dexter OS — Build Roadmap

## Milestone 1 — Dexter OS Preview
Goal: make the current Meizu behave like a Dexter-owned phone without wiping it.

Deliverables:
- Dexter startup branding after Android boot
- Dexter lock/home experience
- polished home layout
- Control Centre
- Dexter Settings
- Staff / Owner modes
- managed Internet
- Dexter Messages team chat
- Dexter Chat customer messaging
- Dexter Send notifications and campaigns
- Dexter Store with approved Google Play apps
- business app catalogue
- notifications surface
- device health panel
- remote support
- remote reboot
- autonomous app updates

Exit test:
A staff member can use the phone for a full shift without entering ordinary Android settings.

## Milestone 2 — Fleet Edition
Goal: prepare Dexter OS for multiple Dexter team phones.

Deliverables:
- team enrolment
- named devices
- staff assignment
- roles and permissions
- remote configuration
- staged app rollout
- lost mode
- audit history
- owner dashboard
- policy templates

Exit test:
A new phone can be enrolled and become a usable Dexter team phone with minimal setup.

## Milestone 3 — Hardware Feasibility
Goal: decide whether the Meizu can safely run a true Dexter OS build.

Deliverables:
- bootloader state report
- fastboot report
- partition map
- Treble/GSI report
- AVB report
- recovery/stock image plan
- hardware compatibility matrix

Exit test:
We can return the device to stock after a failed test.

## Milestone 4 — Dexter OS Developer ROM
Goal: boot a Dexter-branded AOSP-compatible build on a test handset.

Deliverables:
- Dexter SystemUI
- Dexter launcher
- Dexter Settings
- Dexter device agent
- managed browser
- role system
- OTA client
- core hardware drivers working

## Milestone 5 — Dexter OS Team Beta
Goal: controlled daily use by Dexter staff on non-critical handsets.

Required validation:
- calling / messaging
- Wi-Fi
- Bluetooth
- camera
- audio
- battery life
- charging
- notifications
- business apps
- updates
- recovery
- device management

## Milestone 6 — Stable
Only after beta passes:
- signed stable releases
- recovery images
- rollback procedure
- fleet deployment
- documented owner/admin process
